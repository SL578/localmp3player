### The scheme trap, if another target is ever hand-added

The project had **no `.xcscheme` files at all** — Xcode autocreated one per
target from the target list. Adding `ShareExtension` therefore added a scheme,
and with equal order hints Xcode picks the alphabetically first: capital `S`
sorts before lowercase `l`, so the picker silently switched to `ShareExtension`
and ⌘R started asking "choose an app to run" (which is Xcode asking which host
app to inject an *extension* into).

Fixed by committing a real shared scheme at
`localmp3player.xcodeproj/xcshareddata/xcschemes/localmp3player.xcscheme`, and
hiding the ShareExtension scheme in the user's `xcschememanagement.plist`
(`xcuserdata/` is gitignored, so that half is local only, and Xcode rewrites it
from memory on quit — it may reappear in the list, which is cosmetic).

**Editing scheme files while Xcode is running does nothing.** The active scheme
lives in Xcode's in-memory UI state. Restarting Xcode is what applied it.

### The simulator trap that cost this session the test library

`xcrun simctl uninstall` **deletes the app's data container** — library, tags,
playlists, palette, interface mode, everything. It was run to make the simulator
notice the newly added share extension, and that was never necessary:
`xcrun simctl install` over the existing install registers new PlugIns fine.

Reach for `install` only. If an uninstall is genuinely unavoidable, back the data
container up *and verify the copy* first:

```bash
cp -R "$(xcrun simctl get_app_container <UDID> com.lin.localmp3player data)/" backup/
```

The user's response was "don't sweat about deleting testing data, it's for
testing anyways" — but the four real songs in `testSongs/` were the only copies
of the parsing material, and they survived on the Mac. Don't rely on that twice.

### The other simulator trap, still true

`xcrun simctl install` exits 0 and creates a new bundle directory, but
`xcrun simctl launch <old-identifier>` starts whatever was installed under the
*old* identifier. **"BUILD SUCCEEDED" plus a successful install is not evidence
that the app on screen is your build.** After every install:

```bash
ps -Ao pid,comm | grep localmp3player          # which bundle is actually running
```

And to check the binary really has your change — the top-level `localmp3player`
executable is a thin stub, the code lives in the debug dylib:

```bash
LC_ALL=C grep -a -c "<a new string literal>" <app>/localmp3player.debug.dylib
```

### Logging from the simulator

`NSLog` and `print` do **not** reach `xcrun simctl spawn <UDID> log show`, and
`--console-pty` redirected to a file captures nothing. What works is writing to a
file in the app's own Documents directory and reading it from the host. That is
how the toolbar dimming was diagnosed this session; it took about five minutes
and settled a question two sessions had guessed at. Do that; don't burn time on
the log stream.

## What changed this session

Eight reported bugs. Seven fixed, one turned out to be an OS limitation and was
fixed a different way.

### Multi-select share — needed a Share Extension target

**The app was not dropping files. iOS was only ever offering one.**

`onOpenURL` hands over a single URL, so the first theory was that SwiftUI was
lossy. It is not: a custom `UISceneDelegate` reading `scene(_:openURLContexts:)`
— the one place a whole batch could appear — was instrumented and iOS delivered
**exactly one context for a four-file share**. The "Open in Local Player" entry a
document-types app gets from `CFBundleDocumentTypes` is a single-document channel
by design.

A share extension is the only way to be offered the whole selection. New second
target:

- `ShareExtension/ShareViewController.swift` — no compose UI. It copies every
  attachment whose registered type conforms to `.audio` into the App Group
  container and reports what it took.
- `Shared/SharedImportInbox.swift` — the App Group id, the `SharedInbox` folder,
  and `uniqueDestination`. **Compiled into both targets** by listing one
  `PBXFileSystemSynchronizedRootGroup` in both targets' `fileSystemSynchronizedGroups`.
  That works, and it is much less trouble than build-file exception sets.
- `ShareExtension-Info.plist` and `ShareExtension.entitlements` live at the repo
  root, next to the app's own, so the synchronized folder holds only Swift.

Verified end to end: four files in Files ▸ Share ▸ Local Player ▸ **"Add 4"** in
the review sheet.

**iOS will not let a share extension launch its host app.** Both
`NSExtensionContext.open` and the responder-chain `openURL:` fallback are
refused. The extension therefore shows a small card — *"4 songs ready — Open
Local Player to name and add them"* — and the user switches over themselves. The
files are already in the shared inbox, so nothing is lost; the app drains it on
launch, on foreground, and on `localplayer://import`. The code still tries the
open first, in case a device behaves differently.

**Ordering matters in the extension.** Calling `completeRequest` before the
asynchronous `open` tears the extension down and the open never lands. The
request is finished from inside the completion.

`SceneDelegate` is kept even though iOS only sends one URL: it takes the whole
set whenever there is one, and `ExternalURLInbox` parks a launch-time share until
`RootView` exists to collect it.

### Tapping a song plays it and stays put

`SongListContent` and `PlaylistDetailView` each pushed their own
`NowPlayingView` onto the current stack. That was the second way into the player,
arriving from a different edge with a different exit control. Both pushes are
gone. **The mini bar is the only way in**, so there is one player screen with one
design, and its dismiss control is a leading chevron rather than a trailing Done.

### Toolbar glyphs no longer grey out

UIKit sets `tintAdjustmentMode = .dimmed` on the *presenting view controller's
view* for as long as anything is presented over it — instrumented and confirmed:
the root view controller goes `1` → `2` → `1` around the player sheet. Everything
taking its colour from `.tint` greys out with it.

The first attempt put `foregroundStyle` on the `Button` and only half worked,
which is the useful part:

**A `Text` label inherits a foreground style set on its button. An SF Symbol does
not.** That is why Done and Select All survived while Shuffle and Import didn't,
and why Sort was fine from the start — it was already drawing an `Image` with its
own colour stated.

Every navigation-bar icon now goes through `ToolbarGlyph`, which puts the colour
on the symbol; text buttons use `.toolbarTint()`.

**Reproducing it needs Standard mode** — Performance mode has no presentation
animation, so there is no window in which to see it, and a session was lost
testing in the wrong mode. A screenshot-stable repro: Library ▸ Select ▸ tick a
song ▸ trash. The confirmation dialog dims the root while leaving the toolbar
visible.

### Swipe-to-like has a threshold the app chooses

`swipeActions(edge:)` gives no control over its full-swipe trigger. Measured on
an iPhone 17 (402pt row): a 200pt pull (50%) only parks the button open, 240pt
(60%) fires it.

`LikeSwipe` (new) replaces the *leading* swipe action with the app's own gesture,
firing at **45% of the row's width**, with a haptic on crossing. The trailing
edge is untouched and still uses `swipeActions`.

**`simultaneousGesture`, not `gesture` or `highPriorityGesture`.** The row is
still a `List` row; the scroll view's pan and the trailing swipe's recognizer
both have to keep working. The gesture commits to an axis after 10pt and only
ever acts on a horizontal, rightward drag. Verified: scrolling, trailing swipe,
tap-to-play and closing an open trailing swipe all still behave.

The user asked for "75% of the range". Read as three-quarters of the travel it
currently demands, since 75% of the row would be *more* movement than the ~58%
UIKit was already asking for. **One constant if that reading was wrong.**

Lost in the change: swiping partway to reveal a tappable Like button. It is now
past-the-threshold or nothing.

### Artwork upgrades itself

`ArtworkRefresher` ▸ `ArtworkUpgrade` (renamed file too). No longer a Settings
button — "should my artwork be the right size?" has one answer. It runs once in
the background from `RootView`'s `task`, gated by a `artworkUpgradeCompleted`
default that is set **only after a complete pass**, so a run interrupted by the
app being killed is picked up next launch. Import has stored art at full size
since 2026-08-26, so there is nothing for it to do on anything imported since.

### Settings lost two things

## Decisions worth not re-litigating

Carried over and still true:

**Never put a custom `ButtonStyle` in a List's environment.** `swipeActions`
builds its actions from the `Button`s you declare, and with a custom style in
scope it produces *none*. Buttons inside lists use `accentAction(theme)`.

**The palette goes on list content, not the app root.** An explicit
`foregroundStyle` outranks `.tint`.

**Tag exclusions use `SUBQUERY(...).@count == 0`,** not `NOT (ANY tags.id == x)`.

**`SmartPlaylistDetailView` renders an array, not a `@FetchRequest`.**

**Settings pushes by value.** **`EditButton` is not used anywhere.** **Delete
confirmations show only a Delete button.** **Sliders mean edit, a pencil means
rename.** **Core Data gets a new model version rather than an edit in place.**
**Playlist selection is keyed by `PlaylistEntry.id`.** **Toolbar item budget on a
pushed screen is four compact trailing icons with a short title.** **Tab panes
are kept alive behind an opacity change,** so `popSignal` exists.

**Don't trust `Slider.onEditingChanged` for "the drag ended" on iOS 26.** Any
control that needs to know when a finger lifted should own its own `DragGesture`.

**`ScrubBar` uses `highPriorityGesture`, not `gesture`.** It lives in a
`ScrollView` and a slightly diagonal scrub would otherwise be handed to the
scroll view mid-gesture.

**A `play()` re-issue after setting `AVAudioPlayer.currentTime` is not needed.**
Tested with the line disabled: playback resumes on its own. Don't re-add it.

**`AudioFileStore.stageFile` must not delete its source unconditionally.**
`AudioFileStore.Origin` decides; only the picker's temp copies, the app's own
`Documents/Inbox`, and the share extension's shared inbox are disposable.

**An incoming share must not enter the scanning phase while the review sheet is
open.** `phase` leaving `.reviewing` makes `isPresentingReview` false, which the
sheet's dismissal binding reads as the user closing it.

**Incoming URLs are buffered for 400ms before staging.** How many callbacks a
share produces is not something the app gets to know.

**Parser rules are deliberately narrow, each guarded by the case that would
break it.** `AC/DC`, `20 ft Under`, `Level 42`, `Sum 41` all survive.

New this session:

**Multi-file sharing needs a share extension. Full stop.** The document-types
route delivers one URL, measured at the scene-delegate level. Don't re-derive it.

**An SF Symbol does not inherit a foreground style set on its enclosing
`Button`; a `Text` does.** Colour toolbar glyphs on the `Image`, via
`ToolbarGlyph`.

**Test the dimming in Standard mode.** Performance mode has no presentation
animation to see it in.

**One `PBXFileSystemSynchronizedRootGroup` can be listed in two targets'
`fileSystemSynchronizedGroups`**, which is how `Shared/` reaches both. No build
file exception sets needed.

**Hand-adding a target adds a scheme.** Commit a shared `.xcscheme` for the app
at the same time, or Xcode's autocreated schemes will fight over the picker.

**`simctl uninstall` is never the answer.** See above.

## Known issues / open items

- **The share extension cannot bring the app forward.** Not fixable from the app
  side. The card tells the user to switch over. Worth re-testing on a physical
  device, where the behaviour may differ — the code already tries the supported
  route first.
- **Move-or-delete-the-original on import is deliberately not built.** The user
  flagged it as future work and said the current copy-only behaviour is "okay for
  testing since it allows for repeat imports and deletions". To finish it: switch
  `DocumentPicker` to `asCopy: false`, hold the security scope from pick through
  commit, and delete on successful commit only. **Ask first whether it should
  move or delete, be a setting or the default, and confirm per file or run
  silently** — this is the one feature that destroys data if it is wrong.
- **Tag detail screens show no title in Performance mode.** `TagDetailView`
  applies `modeNavigationChrome` with a large title, and `ModeStyling`'s own
  comment says a visible toolbar background hides a large navigation title on
  iOS 26. Pre-existing; `PlaylistDetailView` doesn't apply it and is fine.
  Flagged to the user, not yet actioned.
- **The like-swipe threshold is one constant** (`LikeSwipe.triggerFraction`,
  currently `0.45`). Awaiting the user's verdict on feel.
- **The play/pause fade removal was never visually confirmed frame-by-frame.**
- **`ワールドイズマイン CPK! Remix` keeps its remix name.** Judged that a remix
  name is part of the title; offered to strip trailing remix credits, awaiting a
  call.
- **The rule migration path has still never met real data.**
- **The `colorHex` migration has only met the simulator's store.**
- **Tag colors and playlist colors fall back differently** — playlists use
  `tint(theme)` for nil, tags still use `Color(hex:) ?? .gray`.
- **The Library tab is not wired to pop-to-root.**
- **The Library's toolbar collapses sort and import into a "..." menu while
  selecting.** Pre-existing.
- **No test target.** Worth re-offering now that the project has a second target
  and the pbxproj has been shown to be safely hand-editable. The parser
  regressions are a ready-made first suite.
- **Drag-to-reorder is still unverified by automation.**
- `ArtworkCache` still decodes synchronously on first hit.
- CarPlay entitlement still not requested; CarPlay paths untouched.

- Simulator used all session: **iPhone 17, `D4DACBFD-572D-42AB-96AF-6FD72E2A3562`**.

  `~/Library/Developer/Xcode/DerivedData/localmp3player-hhbhvdugsegxzpaxxddnxlogcfmg/Build/Products/`.
- To get files into the simulator for import testing, copy them into the app's
  own `Documents/` — `UIFileSharingEnabled` plus `LSSupportsOpeningDocumentsInPlace`
  make it browsable in Files as "Local Player". **Files caches its listing**; if
  a freshly copied folder shows as empty, launch the app once and navigate out of
  and back into the folder.
- **Horizontal swipes need a duration.** `swipe` with `duration: 0.8` works.
- Point space is 402 × 874 on iPhone 17. **Screenshots come back ~919px wide, so
  divide image coordinates by ~2.29.**
- **A tab remembers where you left it**, so tapping a tab may land on a pushed
  detail screen. Screenshot before tapping by coordinate.
- **The mini bar shifts every row below it.** Coordinates taken while something
  was playing are wrong once playback stops. Screenshot before each tap in a
  sequence.
- **The user tests alongside you in the same simulator.** Don't assume the app
  state is yours.

reports bugs by symptom and expects the cause found; wants to be told what was
