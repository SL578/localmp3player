### The simulator trap that ate forty minutes of this session

`xcrun simctl install` exits 0 and creates a new bundle directory, but
`xcrun simctl launch <old-identifier>` cheerfully starts whatever was installed
under the *old* identifier. With two identifiers in play, every install went one
way and every launch went the other, so **a build from hours earlier kept running
and every fix looked like it did nothing.** Several "the fix didn't work"
conclusions this session were drawn against stale code and had to be re-tested.

After every install, before trusting any observation:

```bash
ps -Ao pid,comm | grep localmp3player          # which bundle is actually running
xcrun simctl listapps <UDID> | grep -A3 localmp3player
```

And to check the binary really has your change — note the top-level
`localmp3player` executable is a thin stub, the code lives in the debug dylib:

```bash
LC_ALL=C grep -a -c "<a new string literal>" <app>/localmp3player.debug.dylib
```

**"BUILD SUCCEEDED" plus a successful install is not evidence that the app on
screen is your build.**

### Logging from the simulator

`NSLog` and `print` did **not** reach `xcrun simctl spawn <UDID> log show`, and
`simctl launch --console-pty` redirected to a file (even through `script`)
captured nothing. What worked was writing to a file in the app's own Documents
directory and reading it from the host. If you need traces, do that; don't burn
time on the log stream.

### `da09894` — the progress bar seeks, and the play button answers instantly

**The progress bar never seeked at all.** `Slider` gives exactly one signal for
"the finger left the screen" — `onEditingChanged(false)` — and **on iOS 26's
fluid slider that call never arrives.** `isScrubbing` was set on first touch and
only cleared by that callback, so it latched on permanently: the thumb and the
elapsed label were pinned to the scrub position for the rest of the session,
`seek` was never called, and the stale value carried across song changes.
Dragging to 14:30 and pressing next put 14:30 into a three-minute song, which
ended it immediately and skipped to the one after. That was the whole reported
symptom, from one latched boolean.

`ScrubBar` (new, `UI/ScrubBar.swift`) owns the gesture, so it owns the end of it.
Tap-to-seek falls out of the same path: a `DragGesture(minimumDistance: 0)`
reports a tap as a drag that ends where it began.

`PlaybackController.seek` was fine and is **unchanged**.

The play/pause cross-fade was SF Symbols interpolating by default when the name
behind an `Image` changes. `instantSymbolSwap` (in `ModeStyling`) turns it off
with `contentTransition(.identity)` plus a nil animation, in *both* interface
modes.

### `ae29741` — cover art at the size the app draws it

320px at JPEG 0.8 against a 260pt square that needs 780 physical pixels at 3x —
every cover was upscaled 2.4x over artefacts baked in at a size never meant to be
seen that large. Now 1024px at 0.92, roughly 180–220KB each.

`ArtworkRefresher` + Settings ▸ **Upgrade Artwork** re-reads art for songs already
in the library, since only the imported file still holds the full picture. It
skips songs already at full size and only writes when the art read is genuinely
bigger, so re-runs don't rewrite identical bytes.

### `8c44186` — video-download tags, and files shared into the app

All four of the user's test files are yt-dlp downloads: the **title frame holds a
video title** and the **artist frame holds the uploading channel**. Taking them at
face value produced *"Tchaikovsky - The Nutcracker Suite, Op 71a"* by
*"avrilfan2213"*, and skipped `FilenameParser` entirely because tags were present.

The source URL yt-dlp writes into the ID3 user-text (`TXXX`) frames is what tells
the two shapes of file apart. Real music tags are still taken as the answer; these
get the filename cleanup applied to the tag instead — better input, because the
tag still holds characters the filesystem made the *name* drop. An artist named
inside the title now outranks the channel.

Sharing/opening an audio file into the app works via `CFBundleDocumentTypes` +
`onOpenURL`. Verified end to end through Files ▸ Open With ▸ Local Player.

## Decisions worth not re-litigating

Carried over and still true:

**Never put a custom `ButtonStyle` in a List's environment.** `swipeActions`
builds its actions from the `Button`s you declare, and with a custom style in
scope it produces *none*. Buttons inside lists use `accentAction(theme)`.

**The palette goes on list content, not the app root.** An explicit
`foregroundStyle` outranks `.tint`.

**Tag exclusions use `SUBQUERY(...).@count == 0`,** not `NOT (ANY tags.id == x)`.

**`SmartPlaylistDetailView` renders an array, not a `@FetchRequest`.**

**Settings pushes by value.** **`EditButton` is not used anywhere.** **Delete
confirmations show only a Delete button.** **Sliders mean edit, a pencil means
rename.** **Core Data gets a new model version rather than an edit in place.**
**Playlist selection is keyed by `PlaylistEntry.id`.** **Toolbar item budget on a
pushed screen is four compact trailing icons with a short title.** **Tab panes
are kept alive behind an opacity change,** so `popSignal` exists.

New this session:

**Don't trust `Slider.onEditingChanged` for "the drag ended" on iOS 26.** It is
the only end signal `Slider` offers and it does not fire. Any control that needs
to know when a finger lifted should own its own `DragGesture`.

**`ScrubBar` uses `highPriorityGesture`, not `gesture`.** It lives in a
`ScrollView`; a scrub is mostly horizontal but a slightly diagonal one would
otherwise be handed to the scroll view mid-gesture and the bar would never hear
that it ended — reintroducing exactly the latch that was just fixed.

**A `play()` re-issue after setting `AVAudioPlayer.currentTime` is not needed.**
It was added on the theory that the player stalls at the new offset, then tested
with the line disabled: playback resumes on its own. Removed rather than left in
with a comment asserting something untested. Don't re-add it on a hunch.

**`AudioFileStore.stageFile` must not delete its source unconditionally.** That
was safe only while every URL came from the picker in `asCopy: true` mode. With
`LSSupportsOpeningDocumentsInPlace` a shared file is a reference to the user's
actual document, and the old line would have deleted the original off the device.
`AudioFileStore.Origin` decides; only the picker's temp copies and the app's own
`Documents/Inbox` are disposable.

**An incoming share must not enter the scanning phase while the review sheet is
open.** `phase` leaving `.reviewing` makes `isPresentingReview` false, which the
sheet's dismissal binding reads as the user closing it — and that calls
`cancelReview`, discarding every draft including the ones being added.

**External URLs arrive one per `onOpenURL` callback** even when several files
were shared together, so they are buffered for 400ms before staging. Without
that, sharing four songs opened the review sheet four times, each throwing away
the last.

**`onOpenURL` selects the Library tab first.** The review sheet hangs off
`LibraryView`, and all panes are alive behind an opacity change, so presenting
from a non-visible pane puts the sheet over the wrong screen.

**Parser rules are deliberately narrow, each guarded by the case that would
break it.** Slash split only when the left side is a phrase (`AC/DC` keeps its
name). Trailing `feat.` not after a digit (`20 ft Under` keeps its title).
Single-letter catalogue numbers require their period (`Level 42`, `Sum 41`
survive). There is a standalone regression harness in the session scratchpad
approach: compile `FilenameParser.swift` with a `main.swift` of assertions —
18 cases passed at the end of this session. **Worth rebuilding as a real test
target rather than re-deriving it.**

**`testSongs/` is gitignored, not committed.** 56MB of material that is not ours
to redistribute from a public repository.

- **If you must uninstall, back up the data container first.** This session did
  `cp -R "$(xcrun simctl get_app_container <UDID> <id> data)/" backup/`, then
  restored `Documents/` and `Library/` afterwards. Preferences live in
  `Library/Preferences/<bundle-id>.plist` and are **keyed by bundle identifier**,
  so a bundle-id change loses theme and interface mode unless the plist is copied
  across under the new name.
- To get files into the simulator for import testing, copy them into the app's
  own `Documents/` — `UIFileSharingEnabled` plus
  `LSSupportsOpeningDocumentsInPlace` make it browsable in Files as "Local
  Player".
- **Horizontal swipes need a duration.** `swipe` with `duration: 0.8` works.
  `touch_path` for a drag was less reliable than `swipe` for the scrub bar.
- Point space is 402 × 874 on iPhone 17. **Screenshots come back ~919px wide, so
  divide image coordinates by ~2.29.**
- **A tab remembers where you left it**, so tapping a tab may land on a pushed
  detail screen. Screenshot before tapping by coordinate.
- **The user tests alongside you in the same simulator.** Don't assume the app
  state is yours.
- **Put test data back.** This session restored the library, tags, theme and
