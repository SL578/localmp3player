## What changed this session

### Smart playlists, rebuilt (`b0285ea`)

Driven by `docs/smart-playlist-rebuild-prompt.md`. The old model held exactly one
criterion, so "2000s but not rap, except Eminem" was structurally unexpressible.

`SmartRule` is now one value type carrying tag **and** artist criteria at once:
include (with any/all for tags), exclude, and an except-override. A song
qualifies when every non-empty criterion passes; the override rescues a song from
an *exclusion only* — it never pulls back in one that failed the include. Stored
as JSON in the existing `ruleData` Binary attribute, so no Core Data migration.
`SmartPlaylist.rule` reads all three historical shapes and upgrades on next save.

The editor is one scrolling form: Must Have / Must Not Have / Except If Has as
removable chips, a shared searchable Tags+Artists picker sheet, More Filters
collapsed underneath, and a live match count that taps through to a preview.

Verified against the spec's worked example on real data: Tag 1 required, Tag 2
excluded, Tag 3 as exception → 2 matches, with the excluded-but-rescued song in
and the one failing the include still out.

### Interaction and editing

- Swipe right on a song to like; swipe left on songs, tags, playlists and smart
  playlists for Edit and Delete.
- Every destructive delete confirms first (`UI/DeleteConfirmation.swift`).
- `SongEditor` — song metadata is editable after import, recomputing
  `normalizedKey` so duplicate detection stays correct.
- Tags and manual playlists can be renamed; smart playlist rules are reachable
  from inside the playlist.
- One edit glyph app-wide, named in `Style/AppSymbols.swift`.

### Appearance

- Custom background/text colors now reach every screen, not just Settings.
- Playlists and Tags match the Library: flat rows, no card bubbles, searchable.
- Settings folds interface and theme into one **Appearance** section; the
  light/dark picker inside it is labelled **Theme**.
- Standard mode's tab bar captions only the selected tab, in a glass bubble;
  Performance keeps the original captioned bar.
- Dark is the default on a fresh install.

## Decisions worth not re-litigating

**Never put a custom `ButtonStyle` in a List's environment.** `swipeActions`
builds its actions from the `Button`s you declare, and with a custom style in
scope it produces *none* — UIKit then disables the swipe entirely. This silently
killed every swipe in the app for two rounds; scrolling kept working, which is
what made it hard to spot. Buttons inside lists use `accentAction(theme)`
instead. The comment on that helper records why.

**The palette goes on list content, not the app root.** An explicit
`foregroundStyle` outranks `.tint`, so setting it at the root repainted every
toolbar button in the text color and Cancel/Save/Select stopped looking
tappable. `themedScrollBackground` applies it to content; toolbars are left to
the tint.

**Tag exclusions use `SUBQUERY(...).@count == 0`, not `NOT (ANY tags.id == x)`.**
The SQL store turns that negation into "has some tag that isn't x", true of
anything carrying a second tag — so exclusions never excluded. Compiles fine,
reads correctly, silently wrong.

**`SmartPlaylistDetailView` renders an array, not a `@FetchRequest`.** A rule can
end in a random sample, which no single fetch request expresses. It refreshes on
`NSManagedObjectContextDidSave` so edits from that screen still land.

**Settings pushes by value.** A `NavigationLink` carrying its own destination
pushes through private state the `path` binding never sees, so clearing the path
did nothing and Colors stayed open across tab switches.

**`EditButton` was replaced by a hand-rolled toggle** in `PlaylistDetailView`: it
drives whatever `editMode` it finds rather than the one the toolbar reads, which
left the toolbar unable to tell whether the list was being edited.

**Delete confirmations show only a Delete button.** iOS anchors them to the row
as a popover and drops the cancel button there; tapping outside cancels. System
behavior, not a missing button.

**Sliders mean edit, a pencil means rename.** The user's own distinction.

## Working notes for the simulator

The user **reversed** the earlier "don't use the simulator" instruction — driving
it is fine now. Two things that cost real time:

- **Horizontal swipes need a duration.** `swipe` with `duration: 0.8` works;
  instant swipes and `touch_path` land as *taps*, which at one point opened a
  playlist instead of revealing its row actions. This made a real bug look
  unreproducible.
- Point space is 402 × 874 on iPhone 17. Screenshots come back larger; divide
  image coordinates by ~2.29 at `scale: 0.3`. `attach` reports the point
  dimensions — call it first.
- **The user tests alongside you in the same simulator.** Data changed under me
  mid-session (a playlist renamed, tags edited). Don't assume the app state is
  yours, and don't fight for the screen.
